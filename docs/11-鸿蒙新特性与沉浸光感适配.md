# 鸿蒙新特性与沉浸光感适配（Cirrus / 卷云）

> 平台基线：HarmonyOS NEXT，**targetAPIVersion / compatibleSdkVersion = 26.0.0（API 26）**
> 本文回答一个问题：在 API 26 上，本应用**应当**、**可以**与**不应**使用哪些鸿蒙新能力，以及如何落地。
> 所有结论以华为开发者官网（developer.huawei.com）为准；带「⚠️ 待核对」处须在编码前核实最新 API 与权益。

---

## 0. 版本基线核对

| 项 | 取值 | 依据 |
|----|------|------|
| 目标 API | **26.0.0** | 用户指定；`build-profile.json5`:`compatibleSdkVersion/targetSdkVersion` |
| 沉浸光感启用前提 | **targetAPIVersion ≥ 26.0.0** | 官方「沉浸光感」适配文档明确要求 |
| 关键新增 Kit | **UI Design Kit（UIDesignKit）** | API 26 沉浸光感/HDS 组件载体 |

> 官方版本命名示例：`5.0.0(12)`、`6.0.0(20)`、`6.1.0(23)`、`6.1.1(24)`；`x.y.z(API)` 中括号内为 API 编号。本应用以 **API 26** 为唯一编译/运行基线（不做低版本兼容，属有意决策，见 §8 风险）。

---

## 1. 总原则

1. **原生优先**：仅用官方 Kit/ArkUI 内置能力，不引入未声明的三方 UI/图表库（延续 `02-技术栈文档` §5）。
2. **Kit 化导入**：一律使用 `@kit.*` 聚合导入（`@kit.ArkUI` / `@kit.ArkData` / `@kit.NetworkKit` / `@kit.LocationKit` / `@kit.NotificationKit` / `@kit.BackgroundTasksKit` / `@kit.LocalizationKit` / `@kit.BasicServicesKit` / `@kit.PerformanceAnalysisKit` / `@kit.CoreFileKit` / `@kit.UIDesignKit`），不再直接 `@ohos.*`。
3. **能力分级接入**：以「沉浸光感」为第一眼视觉基石，按设备能力**分级降级**（§2.4），低端设备/模拟器不得因材质而卡顿或白屏。
4. **适用范围守边界**：对每一项新特性都给出「适用/不适用」判定与官方理由，避免为凑新特性而错误接入（§6）。

## 2. 沉浸光感（空间化 Spatial UI）——第一优先级

> 官方最佳实践：[沉浸光感](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-spatiality-immersive)

### 2.1 概念与视觉特性

沉浸光感是一套模拟真实物理光照的高品质视觉与动效体系，赋予组件：

| 特性 | 说明 | 本应用落点 |
|------|------|------------|
| 通透材质 | 毛玻璃背景，内容隐约可见 | 天气卡片、详情分组卡 |
| 渐变模糊 | 标题栏随滑动透明→模糊 | Home 滚动时的标题栏 |
| 按压弹性反馈 | 按压缩放动画 | 城市卡、图标按钮 |
| 按压点光源 | 触点光晕扩散 | Tab、按钮 |
| 材质流光 | 表面微妙流光 | 胶囊导航/悬浮栏 |
| 智能反色 | 前景与底色接近时自动调整 | 动态天空背景上的文字 |

> 该体系与既有设计目标「玻璃拟态 + 动态天空」**天然同源**；规划结论：**用官方沉浸光感材质替代自研 blur 卡片**，避免双套模糊叠加导致性能与观感割裂。

### 2.2 两条落地路径

**路径 A（推荐，框架级）：采用 HDS 系列组件替换传统组件**

- 导航：`HdsNavigation` / `HdsNavDestination`（`@kit.UIDesignKit`）——替代根 `Navigation`，标题栏经 `titleBar.style.systemMaterialEffect` 配置材质，`scrollEffectOpts` 配置滚动渐变模糊。
- 底部页签：`HdsTabs`——替代手机端 `Tabs`，经 `barFloatingStyle.systemMaterialEffect` 配置材质；`barOverlap(true)` 悬浮、`barFloatingStyle.miniBar` 支持「迷你栏」。

**路径 B（组件级）：普通 ArkUI 组件开启系统材质**

- 通用属性：`​.systemMaterial(new uiMaterial.ImmersiveMaterial({ style, interactive, lightEffect }))` 开启；`​.systemMaterial(uiMaterial.Material.empty)` 关闭。
- 组件专属：`Select.menuSystemMaterial`、`Navigation` 标题栏 `systemMaterial`；弹窗类经 `options.systemMaterial`。

> 规划结论：**框架级（路径 A）+ 局部内容区（路径 B）组合**。首眼（标题栏、底部悬浮导航）走 HDS；内容区玻璃卡按需开 `ImmersiveMaterial`。

### 2.3 材质档位与自适应

| 档位 | MaterialLevel | 说明 |
|------|---------------|------|
| 强 | `EXQUISITE` | 全量光效，高性能设备 |
| 均衡（默认） | `GENTLE` | 视觉/性能平衡 |
| 弱 | `SMOOTH` | 仅核心特性，低端设备 |
| 系统自适应 | `ADAPTIVE` | 由系统按算力/性能自动选择（**默认推荐**） |

- 默认使用 `hdsMaterial.MaterialType.ADAPTIVE` + `hdsMaterial.MaterialLevel.ADAPTIVE`。
- 用户可在设置内手动切换档位（对应 `MaterialLevel`，参考官方示例 `customMaterialLevel`）。

### 2.4 能力探测与优雅降级（必做）

```ts
// 版本 + 设备能力双探测后再启用高级材质
import { deviceInfo } from '@kit.BasicServicesKit';
import { hdsMaterial } from '@kit.UIDesignKit';

const canImmersive: boolean =
  deviceInfo.apiAvailable('26.0.0') && hdsMaterial.getSystemMaterialTypes().length > 0;
```

- 不满足时：回退为普通半透明卡片（`backgroundBlurStyle`）或纯色卡，**不得**硬开 `EXQUISITE`。
- ⚠️ 模拟器**不支持** HDS 沉浸视效（点光源/按压阴影/流光/沉浸光感材质），真机才有完整效果——测试须以真机为准。

### 2.5 约束与性能红线（必须遵守）

1. **生效区域有限**：开启后，除弹窗类组件（Popup/Tips/Menu/BindSheet/Toast/Select/各类 Dialog/文本菜单等）与 `Slider`、`Toggle` 外，其余组件**仅在** `Navigation/NavDestination 标题栏` 或 `barPosition = BarPosition.End 的底部 TabBar` 中生效。→ 内容区想要材质必须显式用 `ImmersiveMaterial`。
2. **GPU 开销大**：沉浸光感消耗大量 GPU，须阅读官方「沉浸光感功耗优化」；本应用约束：单屏材质控件数量上限、滚动期暂停粒子动效（见 `08-设计规范UIUX.md` §6）。
3. **同层渲染限制**：API 23 及以前在 Web 同层渲染场景下控件会变透明；API 26 已越过该限制，但若后续 WebView 内嵌 ArkUI 控件仍建议关闭其沉浸光感。
4. **亮色模式注意**：`EXQUISITE` 可能覆盖白色叠层；底色为非白纯色时可切 `GENTLE`。
5. **目标 API 门槛**：`targetAPIVersion < 26.0.0` 无法启用——本应用恰好为 26，满足。

### 2.6 智感握姿（Smart Reach）——宽屏交互

- 宽屏设备上，底部悬浮导航可**跟随握持手左右切换**位置：`barFloatingStyle.adaptToHandedness = true`。
- 与 MiniBar 联动：宽屏默认展开、窄屏默认折叠（系统自动，无需手写）。
- 规划结论：**平板/PC 的左/右手跟随导航纳入 v1**（提升大屏单手持握体验，呼应 PRD「全场景」）。

### 2.7 标题栏动态显隐

- `dynamicHideTitleBar({ hideTitleArea, hideStatusBar, mode })`；`HideMode` 支持 `SCROLL_UP_TO / SCROLL_UP / SCROLL_DOWN / SCROLL_UP_TO_BLEND_SCROLL_UP`。
- `bindToScrollable([scroller])` 绑定内容滚动容器，使标题栏/状态栏模糊度与透明度随滚动同步变化。
- 规划结论：Home 页采用 `SCROLL_UP_TO`（上滑固定位隐藏、下滑固定位显示），营造沉浸首眼。

## 4. 状态管理 V2（ArkUI 声明式）

> 现有 `05-架构设计文档`/`Index.ets` 仅用 V1（`@State/@Prop/@Link/@Observed/@ObjectLink`）。API 26 已完整支持 **状态管理 V2**，且 V1/V2 可在组件间混用（API 19+）。

| 场景 | V1（现状） | V2（建议目标） |
|------|-----------|----------------|
| 组件内部状态 | `@State` | `@Local` |
| 父→子单向 | `@Prop` | `@Param`（+ `@Once` 仅初始化一次） |
| 子→父事件 | 回调 props | `@Event` |
| 跨层级 | `@Provide/@Consume` | `@Provider/@Consumer`（可带默认值，API 20+） |
| 观察类 | `@Observed/@ObjectLink` | `@ObservedV2/@Trace` |
| 派生值 | 手动计算 | `@Computed` |
| 深层监听 | `watch` | `@Monitor` |
| 全局/持久 | `AppStorage/PersistentStorage` | `AppStorageV2/PersistenceV2` |
| 循环渲染 | `ForEach` | `Repeat`（可观测组件内部状态） |

- 规划结论：**新代码统一 V2**（`@ComponentV2` + `@Local/@Param/@Event/@ObservedV2/@Trace/@Monitor/@Computed` + `AppStorageV2`）；存量 V1 组件在重构时逐步迁移，**禁止**在 `@ComponentV2` 内混用 V1 装饰器（官方混用有严格规则）。
- 全局信号（当前位置/主题/源/语言/材质档位）改用 `AppStorageV2.connect()` / `PersistenceV2` 持久化。

## 6. 跨设备与系统融合能力的适用性评估

### 6.1 一次开发，多端部署（适用，架构必须对齐）

> 官方：[一次开发，多端部署概览](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-overview)

- **三层工程结构**：`common`（公共能力层）/`features`（基础特性层）/`products`（产品定制层），产品层编译为 Entry HAP。
- **部署模型**：手机+平板+PC+TV 属同一泛类→**模型 A**（相同 HAP）；手表属不同泛类→**模型 B**（独立 HAP）。
- **SysCap 机制**：`deviceTypes` 取各设备能力交集；定位等能力需运行时判定后再启用。
- **能力要素**：断点/网格、窗口沉浸式（状态栏/导航栏避让）、PC/2in1 自由窗口、交互归一（触控/鼠标/键盘/遥控器）。

### 6.2 跨设备数据与接续（部分适用）

- `DistributedKVStore`（`@kit.ArkData`）同步位置与设置——**保留**（见 `06` §5）。
- **应用接续（流转）**：单实例跨设备迁移（手机→平板继续看同一城市）为可选增强，需在 `module.json5` 声明 `continuationEnabled` 并实现 `IAbilityContinuation`。⚠️ 待核对 API 26 上下文与设备支持。

### 6.3 Push Kit 推送（适用，需 AGC）

- 极端天气预警远程推送——**保留**，需要 AGC 应用配置与推送权益。

### 6.4 实况窗（Live View Kit）——**不适用（重要更正）**

> 官方明确：**「天气提示、待办等单点提醒，不属于实况窗」**；且实况窗支持场景清单（TAXI/DELIVERY/FLIGHT/QUEUE…）**不含天气**。实况窗仅 Phone/Tablet、中国境内、需权益申请。

- 结论：**不将天气/预警接入实况窗**，改用：**每日摘要 + 预警的本地通知**（`@kit.NotificationKit`）+ **桌面/锁屏服务卡片**。
- 备注：实况窗自身具备「雨雪天气动效背景」「夕阳/赏月背景」等能力，但那是实况窗的**展示样式**，不构成天气应用可申请的场景。

### 6.5 意图框架（Intents Kit）——**受限可用**

> 官方约束：仅中国境内；Phone/Tablet/PC；**仅面向企业开发者**；不支持模拟器。

- 若具备企业开发者资质：可注册「查询天气」类意图，使小艺搜索/建议/对话可直达本应用（如「小艺，明天要带伞吗」）。**建议列为 P2 增值项**，并在架构预留 `intents` 注册层（不影响主流程）。
- 个人开发者：**不接入**（无法完成意图注册）。

### 6.6 服务卡片（FormExtensionAbility）——适用，补充新形态

- 保留 `WeatherFormAbility` + `forms`（`1*2/2*2/4*2`）。
- 建议评估：锁屏卡片、组合卡片、卡片定时/定点刷新（`updateDuration` 已配 6 小时，与 §7 后台策略对齐）。

## 7. 新特性对后台/刷新策略的修正

| 议题 | 原文档 | 修正结论 |
|------|--------|----------|
| 后台刷新机制 | `@ohos.workScheduler` + `KEEP_BACKGROUND_RUNNING` | 天气周期刷新属**延迟任务**（`@kit.BackgroundTasksKit` WorkScheduler）；`KEEP_BACKGROUND_RUNNING` 是**长时任务**（ContinuousTask）所需权限，二者不可混同。⚠️ 权限声明须据此核对，避免多声明敏感权限 |
| 刷新频次 | 每日 ≤4 次 | 保留；延迟任务由系统按条件调度更省电 |
| 卡片刷新 | `updateDuration: 6` | 与后台策略统一为「≥4 次/日上限」口径 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| UI Design Kit / 沉浸光感**仅中国境内** | 出海包无法使用 HDS | `common/ui` 抽象「材质层」，境内启用 HDS、境外降级普通 ArkUI；编译期按分发渠道选择实现 |
| 沉浸光感 GPU 开销 | 低端机卡顿/发热 | 强制 `ADAPTIVE`、`getSystemMaterialTypes()` 探测、控制同屏材质控件数、滚动期暂停粒子 |
| 磨砂卡片自研与系统材质叠加 | 双层模糊、观感割裂、性能翻倍 | 统一改走系统材质，移除自研 `blur` 叠加 |
| API 26 单一基线 | 无法安装于旧设备 | 为有意决策；`getSystemMaterialTypes`/`deviceInfo.apiAvailable` 做能力探测，功能降级而非崩溃 |
| 实况窗/意图框架误用 | 审核驳回/无法注册 | 本文 §6.4/§6.5 已明确「不适用/受限」，不纳入主流程 |
| 模拟器无沉浸视效 | 测试结论失真 | 视觉验收一律真机；模拟器只验逻辑 |
