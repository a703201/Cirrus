# 接口文档（Cirrus / 卷云）

> 数据源策略：**多源可插拔**。本文定义统一数据模型、默认源（Open-Meteo）字段与调用方式，并给出扩展源（和风天气 QWeather）的接入示例。
> 基线：HarmonyOS NEXT API 26，端侧通过 `@kit.NetworkKit`（http）直连数据源 HTTPS 接口。

---

## 1. 数据源策略与抽象契约

### 1.1 设计原则
- **端侧直连**：应用直接请求天气源 HTTPS 接口，不经自有后端（隐私友好、零服务器成本）。
- **统一归一模型**：各源返回格式不同，统一映射为内部 `WeatherData` 模型，UI 不感知源差异。
- **可插拔**：每个源实现 `WeatherSource` 接口；设置页可切换；新增源只需实现接口 + 注册。

### 1.2 抽象接口（ArkTS 示意）

```ts
// 归一化后的天气数据模型（UI 消费对象）
export interface WeatherData {
  location: LocationInfo;
  current: CurrentWeather;
  hourly: HourlyPoint[];      // 最多 48 条
  daily: DailyPoint[];        // 最多 16 条
  airQuality?: AirQuality;    // 源支持时填充
  alerts?: WeatherAlert[];    // 源支持时填充
  source: string;             // 来源标识，如 "open-meteo"
  fetchedAt: number;          // 抓取时间戳(ms)
}

export interface WeatherSource {
  readonly id: string;            // 唯一标识
  readonly needApiKey: boolean;   // 是否需要密钥
  getCurrentAndForecast(loc: LocationInfo, lang: string): Promise<WeatherData>;
  searchLocation(query: string, lang: string): Promise<LocationInfo[]>;
  toNormalized(raw: object): WeatherData;  // 原始响应 -> 归一模型
}
```

## 3. 默认源：Open-Meteo（免密钥）

### 3.1 基本信息
- **Base URL**：`https://api.open-meteo.com/v1/forecast`
- **Geocoding**：`https://geocoding-api.open-meteo.com/v1/search`
- **鉴权**：无需 API Key（基于公平使用，建议缓存与限频）。
- **协议**：HTTPS GET；返回 JSON。

### 3.2 天气预报请求示例

```
GET https://api.open-meteo.com/v1/forecast
  ?latitude=31.23&longitude=121.47
  &current=temperature_2m,relative_humidity_2m,apparent_temperature,
          precipitation,weather_code,wind_speed_10m,wind_direction_10m,
          surface_pressure,cloud_cover,visibility,is_day
  &hourly=temperature_2m,weather_code,precipitation_probability,
          precipitation,wind_speed_10m
  &daily=weather_code,temperature_2m_max,temperature_2m_min,
          precipitation_probability,sunrise,sunset,uv_index_max
  &timezone=auto
  &forecast_days=16
  &past_days=1
  &wind_speed_unit=kmh
```

### 3.3 关键响应字段（与归一模型映射）

| Open-Meteo 字段 | 类型 | 映射至归一模型 |
|-----------------|------|----------------|
| `current.temperature_2m` | float | `current.temperature` |
| `current.apparent_temperature` | float | `current.apparent` |
| `current.relative_humidity_2m` | int | `current.humidity` |
| `current.wind_speed_10m` | float | `current.windSpeed` |
| `current.wind_direction_10m` | int | `current.windDir` |
| `current.surface_pressure` | float | `current.pressure` |
| `current.cloud_cover` | int | `current.cloud` |
| `current.visibility` | float | `current.visibility`（m→km 需 /1000） |
| `current.weather_code` | int | `current.weatherCode`（WMO） |
| `current.is_day` | int(0/1) | `current.isDay` |
| `hourly.time[]` | string(ISO) | `hourly[].time` |
| `hourly.temperature_2m[]` | float[] | `hourly[].temperature` |
| `hourly.weather_code[]` | int[] | `hourly[].weatherCode` |
| `hourly.precipitation_probability[]` | int[] | `hourly[].precipProb` |
| `hourly.precipitation[]` | float[] | `hourly[].precip` |
| `daily.weather_code[]` | int[] | `daily[].weatherCodeDay` |
| `daily.temperature_2m_max[]` / `_min[]` | float[] | `daily[].tempMax/tempMin` |
| `daily.precipitation_probability[]` | int[] | `daily[].precipProb` |
| `daily.sunrise[]` / `sunset[]` | string | `daily[].sunrise/sunset` |
| `daily.uv_index_max[]` | float[] | `daily[].uvIndexMax` |

> 注：`visibility` 在 Open-Meteo 以米返回，归一层需换算为 km。空气质量和预警 Open-Meteo 免费层不直接提供，由扩展源（如和风）补充，或通过 `air-quality-api.open-meteo.com` 额外请求（可选，需评估可用性）。

### 3.4 地理编码（城市搜索）请求

```
GET https://geocoding-api.open-meteo.com/v1/search
  ?name=Shanghai
  &count=10
  &language=zh
  &format=json
```
响应 `results[]`：`id, name, latitude, longitude, country, admin1, timezone`。

## 4. 扩展源示例：和风天气 QWeather（需密钥）

### 4.1 基本信息
- **Base URL**：`https://devapi.qweather.com/v7/weather/`（开发版）/ `https://api.qweather.com/v7/`（标准版）
- **鉴权**：请求头 `X-QW-Api-Key: <API_KEY>`（或 `key` 查询参数）。
- **能力**：分钟级降水、空气质量、天气预警（弥补默认源短板，对应 PRD F10/F18）。

### 4.2 关键接口
- 实时：`GET /v7/weather/now?location={lon},{lat}`
- 逐小时：`GET /v7/weather/24h?location=...`
- 逐日：`GET /v7/weather/7d?location=...`
- 空气质量：`GET /v7/airquality/now?location=...`
- 预警：`GET /v7/warning/now?location=...`
- 城市搜索：`GET /geo/v2/city/lookup?location=...`

### 4.3 QWeather → 归一模型映射要点
- `now.temp` → `current.temperature`；`now.feelsLike` → `current.apparent`。
- `now.icon` / `now.text` 需映射到 WMO 代码（建一张 QWeather `icon ID ↔ WMO` 对照表，保证图标/文案统一）。
- 预警 `warning.title/severity/text` → `alerts[]`（severity 映射为 level）。
- 空气质量 `aqi` / `pm2p5` / `pm10` → `airQuality`。

### 4.4 接入步骤
1. 在 QWeather 控制台申请 Key，存储于 `Preferences`（不在代码硬编码）。
2. 实现 `QWeatherSource implements WeatherSource`，完成 `toNormalized()`。
3. 在设置「数据源」列表注册；切换时清空旧缓存以避免模型混用。
4. ✅ **合规前置（硬性门禁）**：启用和风等国内商用天气源**之前**，必须完成：① 服务商资质 / 实名备案核实；② 隐私政策增补该源数据收集条款；③ 设置页该源默认关闭、由用户主动开启并二次告知；④ 通过 `harmonyos-reviewer` 与法务评审。未达标的源不得上线（见隐私文档 §3.1 / §4）。

## 5. 调用方式与客户端约定

### 5.1 ArkTS 调用示例（原生 http）

```ts
import { http } from '@kit.NetworkKit';
import { BusinessError } from '@kit.BasicServicesKit';

export async function fetchWeather(url: string): Promise<string> {
  const req = http.createHttp();
  try {
    const resp = await req.request(url, {
      method: http.RequestMethod.GET,
      connectTimeout: 10000,
      readTimeout: 10000,
      header: { 'Content-Type': 'application/json' }
    });
    if (resp.responseCode !== 200) {
      throw new Error(`HTTP ${resp.responseCode}`);
    }
    return resp.result as string;   // JSON 字符串
  } catch (e) {
    const err = e as BusinessError;
    throw new Error(`fetch failed: ${err.code} ${err.message}`);
  } finally {
    req.destroy();
  }
}
```

> 导入规范：统一使用 `@kit.*` 聚合导入（见 `02-技术栈文档` §1 说明），不再直接 `@ohos.net.http`。

### 5.2 缓存策略
- **本地缓存**：成功响应写入 RDB（按 `location.id + source` 主键），`fetchedAt` 记录时间。
- **新鲜度**：`now()` 缓存有效期默认 30 分钟；`hourly/daily` 默认 3 小时；过期才触发网络刷新。
- **离线优先**：缓存命中直接渲染并标注「更新于 HH:mm」；网络失败回退缓存并提示。

### 5.3 重试与限频
- 单次失败退避重试 1 次（指数退避 1s/3s），仍失败则回退缓存。
- 全局限频：同一源同位置最小刷新间隔 15 分钟（手动强刷豁免但提示）。
- 后台周期刷新经 `WorkScheduler` 每日 ≤ 4 次，避开高峰。

### 5.4 错误码与处理

| 情形 | 处理 |
|------|------|
| 网络不可达 | 回退缓存 + Toast「网络不可用，显示缓存数据」 |
| HTTP 4xx | 源参数/密钥错误；提示用户检查源设置 |
| HTTP 429 | 触发限频退避，延后刷新 |
| 解析失败 | 记录日志，回退缓存，不影响主流程 |
| 位置为空 | 引导用户搜索/授权定位 |

## 6. 速率限制与配额

| 源 | 配额 | 应对 |
|----|------|------|
| Open-Meteo | 公平使用，无硬限（建议 ≤ 10,000 次/天/ IP 量级） | 端侧缓存 + 限频即可满足个人用户 |
| QWeather | 免费版有日调用上限（如 1000 次/天，以官网为准） | 仅当用户主动选该源时启用；严格缓存 |

## 7. 安全与隐私

- **传输安全**：强制 HTTPS，禁用明文；校验证书（系统默认）。
- **密钥保护**：扩展源密钥存于 `Preferences`（可选设备加密），不进代码仓库、不上报。
- **位置最小化**：默认优先近似位置；仅向所选天气源发送经纬度用于查询，不附加身份标识。
- **数据流向透明**：设置页「数据流向」明确列出：位置 → 所选天气源；不共享给广告/分析方。
- **审计**：多源接入时，逐源登记其数据收集行为于隐私政策。
