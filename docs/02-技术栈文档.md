# 技术栈文档（Tech Stack）

> 平台：HarmonyOS NEXT ｜ 语言：ArkTS ｜ UI：ArkUI 声明式 ｜ 模型：Stage

## 1. 选型总览

| 维度 | 选型 | 说明 |
|------|------|------|
| 操作系统 | HarmonyOS NEXT | 不再兼容 AOSP，统一使用鸿蒙原生能力 |
| 应用模型 | Stage 模型 | UIAbility + ExtensionAbility（卡片/后台） |
| 开发语言 | **ArkTS** | 鸿蒙主推语言，强类型、声明式 UI；禁用 `any/unknown` 红线的工程约束（见架构文档） |
| 备选语言 | 仓颉（Cangjie） | 仅作技术储备评估，v1 不采用，避免生态不成熟风险 |
| UI 框架 | **ArkUI（声明式）** | 组件化、状态驱动；响应式布局（栅格/断点） |
| 构建工具 | **hvigor** + DevEco Studio | 官方构建与 IDE |
| 包管理 | **ohpm**（OpenHarmony Package Manager） | 依赖语义化版本管理 |
| 目标 API | **API 26** | compile / target / minSdk 统一 26（用户指定最新稳定版，HarmonyOS NEXT） |
| 状态管理 | **ArkUI 状态管理 V2** | 新代码统一 `@ComponentV2` + `@Local/@Param/@Event/@ObservedV2/@Trace/@Monitor/@Computed` + `AppStorageV2/PersistenceV2`；V1 存量逐步迁移（详见 11 §4） |
| 设计套件 | **UI Design Kit（UIDesignKit）** | HDS 组件（HdsNavigation/HdsTabs/HdsSideBar/HdsListItem…）+ 沉浸光感材质，第一眼视觉基石（详见 11 §2/§3） |
| 视觉体系 | **沉浸光感（空间化 Spatial UI）** | 系统材质毛玻璃、悬浮胶囊导航、智感握姿；替代自研 blur 卡片（详见 11 §2） |

> **导入规范（新）**：一律使用 `@kit.*` 聚合导入（`@kit.ArkUI` / `@kit.ArkData` / `@kit.NetworkKit` / `@kit.LocationKit` / `@kit.NotificationKit` / `@kit.BackgroundTasksKit` / `@kit.LocalizationKit` / `@kit.BasicServicesKit` / `@kit.UIDesignKit` 等），不再直接 `@ohos.*`。

## 2. 核心能力与 Kit 选型

| 能力 | 选用 Kit / API | 用途 | 所需权限 | 设备可用性 |
|------|----------------|------|----------|------------|
| 网络请求 | `@kit.NetworkKit`（http） | 直连天气数据源（HTTPS） | `ohos.permission.INTERNET` | 手机/平板/PC/TV/手表 |
| 本地配置 | `@kit.ArkData`（preferences） | 用户设置、主题、源选择 | 无 | 全设备 |
| 结构化缓存 | `@kit.ArkData`（relationalStore / RDB） | 天气数据、位置表本地缓存 | 无 | 手机/平板/PC/TV |
| 跨设备同步 | `@kit.ArkData`（distributedKVStore） | 位置/设置跨设备一致（同华为账号、组网） | 无（需设备信任） | 手机/平板/PC/TV（手表受限） |
| 定位 | `@kit.LocationKit`（geoLocationManager） | 获取当前位置天气（粗粒度即可） | `ohos.permission.LOCATION` + `ohos.permission.APPROXIMATELY_LOCATION` | 手机/平板/手表 |
| 后台刷新 | `@kit.BackgroundTasksKit`（延迟任务 WorkScheduler） | 周期刷新天气/预警（系统按条件调度，免敏感权限） | 无（延迟任务**不**需 `KEEP_BACKGROUND_RUNNING`；该权限仅用于长时任务） | 手机/平板 |
| 通知 | `@kit.NotificationKit`（notificationManager） | 每日摘要、预警本地提醒 | 无声明；运行时用户授权（`requestEnableNotification`） | 手机/平板/手表 |
| 推送 | **Push Kit**（华为推送） | 极端天气预警远程推送 | 需 AGC 应用配置与推送权益 | 手机/平板 |
| 卡片 | `FormExtensionAbility` | 桌面/锁屏天气卡片 | 无 | 手机/平板 |
| 国际化 | `@kit.LocalizationKit`（i18n/intl）+ 资源限定词 | 多语言、区域格式 | 无 | 全设备 |
| 动画/特效 | ArkUI 内置动画 + `@kit.ArkGraphics2D` | 天气粒子背景、转场（数字翻牌/渐变文本/三维变换见 11 §5） | 无 | 手机/平板/PC/TV |
| **设计/材质** | **`@kit.UIDesignKit` + `@kit.ArkUI`（uimaterial）** | 沉浸光感材质、HDS 悬浮导航/标题栏、智感握姿（仅中国境内；沉浸材质仅 Phone/Tablet） | 无 | 见 11 §3.2 |

> ⚠️ 待确认：部分 Kit 在手表（小型系统）上的可用性以目标 API 级别官方文档为准；手表端走独立轻量入口模块（`watch/`，部署模型 B）。
>
> ⚠️ 重要更正：**实况窗（Live View Kit）不适用于天气**（官方明确「天气提示等单点提醒不属于实况窗」）；**意图框架（Intents Kit）仅企业开发者可用**。二者结论见 `11` §6.4/§6.5，不纳入主流程。

## 3. 第三方库与开源参考

### 3.1 优先「原生 API + 自研轻量封装」
鸿蒙生态对通用 npm JS 库兼容性有限，遵循「能用原生则用原生」原则：

| 用途 | 选型 | 说明 |
|------|------|------|
| HTTP 客户端 | `@kit.NetworkKit`（原生） | 封装统一拦截器（超时/重试/缓存头） |
| JSON 解析/映射 | 原生 `JSON.parse` + 自定义 DTO 映射器 | 每数据源实现 `toNormalized()` 转换 |
| 时间/时区 | `@kit.LocalizationKit`（intl）+ 自研 `DateTimeUtil` | 避免引入未验证的 dayjs 等 JS 库 |
| 图表（温度曲线/降水柱/风羽） | **自绘 Canvas**（`@kit.ArkGraphics2D`） | 完全可控、契合设计语言；评估开源 ArkUI 图表组件作为备选 |
| 天气图标 | 自绘 SVG/PDF 图标集 + 自定义 Symbol 注册 | 参考 Breezy/Geometric 图标美学，分昼夜/多态 |
| 状态管理 | ArkUI **状态管理 V2**：`@ComponentV2` + `@Local/@Param/@Event/@ObservedV2/@Trace/@Monitor/@Computed` + `AppStorageV2/PersistenceV2` | 全局主题/位置信号；仓库层做领域状态 |
| 图片/资源 | 原生 `Image` + `Resource` | 按设备分辨率与主题加载 |

### 3.2 评估引入（需立项时验证 ArkTS 兼容性）
- 若需更丰富图表：调研 OpenHarmony 生态中已验证的 ArkUI 图表组件（如 `mpchart` 鸿蒙移植或官方 `graphics` 示例）。
- 若需响应式工具链：仅限已发布到 ohpm 且声明 ArkTS 兼容的包。

### 3.3 开源架构参考（非代码复用，仅借鉴设计）
- **Breezy Weather（Kotlin，Apache-2.0）**：多天气源可插拔的 `WeatherSource` 抽象、WMO 代码映射、逐小时/逐日数据模型——本项目的多源架构直接受其启发。
- **Geometric Weather（Kotlin，Apache-2.0）**：简洁信息层级、卡片化布局、天气背景动效——本项目的 UI 信息架构参考对象。

> 版权注意：仅借鉴架构与交互思路，不复制其源代码与图标资源；自研图标需独立绘制或采用合规授权素材。

## 5. 依赖最小化原则

1. 默认使用系统 Kit 与 ArkUI 内置能力，不盲目引入第三方库。
2. 多源数据解析、图表、图标一律自研，降低供应链与兼容性风险。
3. 所有外部依赖须在 `oh-package.json5` 中锁定版本，并登记用途与许可证。
