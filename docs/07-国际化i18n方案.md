# 国际化 i18n 方案（Cirrus / 卷云）

> 范围：zh-CN / en-US / ja-JP / ko-KR / fr-FR / es-ES / de-DE 首发，架构预留扩展。
> 机制：HarmonyOS 资源限定词目录 + `@kit.LocalizationKit`（i18n）+ `$r()` 引用。

## 1. 资源目录结构

```
resources/
  base/                     # 默认（fallback，建议放 en-US 或 zh-CN）
    element/string.json     # 通用文案
    element/weather_code.json  # WMO 代码 → 本地化描述
    media/                  # 图标/背景
  zh-CN/  element/string.json  weather_code.json
  en-US/ element/string.json  weather_code.json
  ja-JP/  ...
  ko-KR/  ...
  fr-FR/  ...
  es-ES/  ...
  de-DE/  ...
```

- 文案一律通过 `$r('app.string.xxx')` 引用，禁止硬编码用户可见字符串。
- 资源缺失时回退 `base`；上线前用脚本校验各语种 key 完整性。

## 2. 文案 Key 规范

采用「模块.语义」命名，避免歧义：

| Key 示例 | 含义 |
|----------|------|
| `app.name` | 应用名（按语种显示名） |
| `home.temperature` | 「温度」标签 |
| `settings.source` | 「数据源」 |
| `unit.celsius` | 摄氏度符号/词 |
| `alert.level_warning` | 预警等级文案 |
| `weather.0` … `weather.99` | WMO 代码本地化描述（见下） |

> 注：I18n 资源（`.json`）不支持占位符；动态参数用 `.replace('{x}', val)` 处理（与项目既有规范一致）。

## 3. 天气代码本地化（weather_code.json）

每个语种提供 WMO 代码→描述的映射，UI 依 `weatherCode` 取词：

```json
// zh-CN/element/weather_code.json
{ "weather.0": "晴", "weather.1": "大致晴朗", "weather.2": "局部多云",
  "weather.3": "阴", "weather.45": "雾", "weather.61": "小雨", ... }
// en-US/element/weather_code.json
{ "weather.0": "Clear", "weather.1": "Mainly clear", ... }
```

图标键（`wx_0_day` 等）与代码解耦，文案随语言切换而图标不变。

## 4. 日期 / 数字 / 单位格式化

- 使用 `@kit.LocalizationKit`（i18n/intl）的 `DateTimeFormat` / `NumberFormat` 按当前 `Locale` 格式化。
- 时间显示遵循系统 12/24 小时制设置。
- 单位文案（°C、km/h、hPa、mm、µg/m³）按语言习惯微调（如风速美式可选 mph，但默认 km/h）。
- 星期/月份用 `Intl` 本地化，避免自拼。
- **系统外观联动**：用 `uiAppearance`（`@kit.ArkUI`）读取深浅色/字体缩放/字重缩放比例，保证多语言下排版一致；中英混排可开启 `enableAutoSpacing` 自动间距。
- **时区跳变**：多城市/出境场景用 i18n 时区规则（⚠️ API 20+ 的时区跳变规则接口）处理夏令时与跨时区展示。

## 6. 翻译与校对流程

1. 产品/开发在 `base` 抽取全部 key 与英文基准文案。
2. 交由对应语种校对（天气术语需专业，如「霰」「霧凇」等）。
3. 上线前脚本校验：各语种 key 集合 == base key 集合，缺失即 CI 失败。
4. 气象预警等官方文本以源返回原文 + 必要的本地化呈现，不做机翻误导。
