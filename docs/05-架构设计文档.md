# 架构设计文档（Cirrus / 卷云）

> 模型：Stage ｜ 语言：ArkTS ｜ UI：ArkUI 声明式 ｜ 原则：离线优先 + 多源可插拔 + 跨设备一致

## 1. 分层架构

```
┌──────────────────────────────────────────────────────────┐
│                      UI 层 (features/*)                    │
│  Home / Hourly / Daily / Details / Locations / Settings /   │
│  Alerts / Widget(FormExtension) / Watch(独立入口)           │
└───────────────────────────┬──────────────────────────────┘
                            │ 单向数据流（@State/@Link/@Observed）
┌───────────────────────────┴──────────────────────────────┐
│                    Domain 层 (usecases)                    │
│  GetWeather / RefreshWeather / ManageLocations /            │
│  SwitchSource / SyncAcrossDevices / ScheduleNotify          │
└───────────────────────────┬──────────────────────────────┘
                            │
┌───────────────────────────┴──────────────────────────────┐
│                      Data 层 (repository)                  │
│  WeatherRepository（编排：源 + 缓存 + 刷新策略）            │
│  ├─ sources/*      : OpenMeteoSource / QWeatherSource …    │
│  ├─ local/        : RDB 缓存 / Preferences / DistributedKV │
│  ├─ location/     : geoLocationManager + Geocoding         │
│  └─ scheduler/    : WorkScheduler 周期刷新                 │
└──────────────────────────────────────────────────────────┘
```

## 2. 模块划分（工程结构）

```
entry/                      # 主模块（手机/平板/PC/TV 入口）
  └─ src/main/ets/
      entryability/         # EntryAbility（UIAbility）
      pages/                # 路由页面（Navigation）
features/                   # 垂直功能模块（可独立编译/复用）
  home/        hourly/      daily/       details/
  locations/   settings/    alerts/      widget/      watch/
common/                      # 跨模块共享
  ui/          # 自适应组件库（卡片/图表/图标/背景动效）
  utils/       # DateTimeUtil / UnitUtil / Log（统一日志封装）
  i18n/        # 多语言资源与取词封装
  models/      # WeatherData 等归一模型与 DTO
data/                       # 数据层（见上）
  sources/     local/  location/  scheduler/
```

> 手机/平板/PC/TV 共用 `entry` + `features`；**手表**因系统差异走 `watch/` 独立轻量入口（或独立 module），复用 `data` 与 `common`。

### 2.1 与官方「三层工程结构」对齐（一次开发多端部署）

官方「一多」推荐 **common（公共能力层）/ features（基础特性层）/ products（产品定制层）** 三层结构。本工程对应关系与改进建议：

| 官方分层 | 本工程现状 | 说明 / 改进 |
|----------|-----------|-------------|
| common 公共能力层 | `common`（模型/工具/UI）+ `data`（数据能力） | `common` 编译为 HAR，可被 features/products 依赖，不可反向依赖；`data` 视作公共数据能力层 |
| features 基础特性层 | `entry/.../features/*`（当前为**目录**） | 建议后续将 `home/hourly/daily/details/locations/settings/alerts/widget` 提升为独立 HAR，按需部署、可复用、降低耦合 |
| products 产品定制层 | `entry`（手机/平板/PC/TV）、`watch`（手表） | 各自编译为 Entry HAP；手机/平板/PC/TV 同泛类→**部署模型 A**，手表不同泛类→**部署模型 B** |

- **SysCap**：`deviceTypes` 取各设备能力交集；定位、推送等能力须运行时判定后再启用（`canIUse`）。
- 详见 `11-鸿蒙新特性与沉浸光感适配.md` §6.1 与 `06-多设备适配方案.md`。

## 3. 数据流（离线优先）

```
用户操作/周期触发
   │
   ▼
WeatherRepository.getWeather(loc)
   │
   ├─ 1) 命中 RDB 缓存且未过期 ──► 直接返回（标注 fetchedAt）
   │
   └─ 2) 未命中/过期 ──► 调 source.getCurrentAndForecast()
                              │
                  ┌───────────┴───────────┐
             成功 │                       │ 失败(网络/4xx/429/解析)
                  ▼                       ▼
           toNormalized()            回退 RDB 旧缓存
                  │                       │
              写入 RDB + 更新 AppStorage   └─► 提示「网络不可用，显示缓存」
                  │
                  ▼
            通知 UI 刷新（@State 驱动）
```

- **单一数据源**：UI 只消费 `WeatherData`；`AppStorage` 持有「当前位置 / 主题 / 源选择」等全局信号。
- **缓存键**：`location.id + source`，避免多源数据混淆。

## 4. 状态管理约定

采用 **ArkUI 状态管理 V2**（API 26 完整支持），新代码统一 V2；存量 V1 组件在重构时逐步迁移。

| 范围 | V2 机制（推荐） | 对应 V1 | 示例 |
|------|-----------------|---------|------|
| 组件内部 | `@Local` | `@State` | 列表展开、输入态 |
| 父→子单向 | `@Param`（+`@Once`） | `@Prop` | 天气对象传入 |
| 子→父事件 | `@Event` | 回调 props | 刷新/切换回调 |
| 跨层级提供 | `@Provider/@Consumer` | `@Provide/@Consume` | 主题、材质档位 |
| 深层观测 | `@ObservedV2`/`@Trace` | `@Observed/@ObjectLink` | 天气对象深层更新 |
| 派生/监听 | `@Computed` / `@Monitor` | 手动计算 / `watch` | 温区条、单位换算 |
| 全局信号 | `AppStorageV2` / `PersistenceV2` | `AppStorage/PersistentStorage` | 当前位置、主题、源、语言、材质档位 |
| 跨设备 | `DistributedKV`（`@kit.ArkData`） | 同 | 位置列表、设置项 |
| 循环渲染 | `Repeat`（可观测组件内部状态） | `ForEach` | 逐小时/多日列表 |

> ⚠️ ArkTS 红线（来自工程约束）：`@Component` 上的普通 `get` 访问器会被状态变换器丢弃，改用普通方法；类型标注禁止 `any/unknown`；`catch` 形参需标注具体错误类型（如 `BusinessError`）；**禁止在 `@ComponentV2` 内混用 V1 装饰器**（V1/V2 混用须遵循官方规则）。详见编码规范章节（待补）与 `11` §4。

## 5. 多源可插拔实现

- `sources/` 下每个源实现 `WeatherSource` 接口（见接口文档 §1.2）。
- `WeatherRepository` 持有「当前源实例」，由设置页经 `PersistentStorage` 切换。
- 新增源 = 新建类 + 在源注册表登记 + 补充「源字段→WMO/归一模型」映射表。
- 源切换时清空该位置的旧缓存，防止模型混用。

## 6. 后台与推送

- **周期刷新**：`WorkScheduler` 注册网络类型条件任务，每日 ≤ 4 次，触发 `RefreshWeather`用例。
- **预警推送**：Push Kit 下发，应用接收后在「预警」页呈现并触发本地通知。
- **每日摘要**：`WorkScheduler` + `@kit.NotificationKit` 定时生成摘要。

## 7. 错误处理与韧性

| 故障 | 策略 |
|------|------|
| 网络失败 | 回退缓存 + 明确提示，主流程不崩 |
| 源限频 429 | 指数退避，延后刷新 |
| 解析异常 | try/catch 包裹，记录日志，回退缓存 |
| 位置缺失 | 引导搜索/授权，不阻塞其它位置展示 |

- `DistributedKV` 在 TV/PC 上的组网同步可用性核实。
